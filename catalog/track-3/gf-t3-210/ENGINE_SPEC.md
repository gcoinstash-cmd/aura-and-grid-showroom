Proprietary Mathematical & Algorithmic Engine ### A. Level 2 / Level 3 Price-Time Priority Matching Model Orders are organized into discrete price levels. Within each level P_i, orders reside in a double-ended queue maintaining strict FIFO priority: - Price Priority: Buy orders at higher price ticks precede orders at lower price ticks; Sell orders at lower price ticks precede orders at higher price ticks. - Time Priority: For two orders at identical price P_i, order O_a with timestamp t(O_a) < t(O_b) has strict precedence. - Crossing Rule: For limit buy price P_buy and resting best ask P_ask*, if P_buy >= P_ask*, execution occurs immediately at P_ask* until quantity is exhausted or price constraint is violated. ### B. Queue Position & Fill Survival Estimation For a participant child order O_u resting at price level P_k behind maker volume V_ahead: V_ahead = sum_{j=1}^{m-1} Q_j where Q_j is the remaining quantity of maker orders submitted prior to O_u at P_k. The analytical fill probability P_fill(O_u, delta_t) within time horizon delta_t incorporates distance from the touch delta_P = |P_k - P_touch| and queue depth: P_fill(O_u, delta_t) = exp(-gamma * (delta_P / delta_tick)) * (1 / (1 + V_ahead / kappa)) * (1 - exp(-lambda_hawkes(t) * delta_t)) where gamma = 0.25, delta_tick = 0.05 pts, kappa = 8000 Units, and lambda_hawkes(t) is the instantaneous Hawkes intensity. ### C. Univariate Hawkes Self-Exciting Point Process Trade arrivals exhibit clustering and endogenous feedback described by: lambda(t) = mu + sum_{t_i < t} alpha * exp(-beta * (t - t_i)) - mu: Exogenous baseline intensity (unconditional Poisson arrival rate = 1.5 events/sec) - alpha: Self-excitation parameter representing endogenous cross-impact per execution (0.75) - beta: Exponential decay rate governing memory relaxation (1.20) Stationarity Invariant: eta = alpha / beta < 1.0 - eta < 1.0: Sub-critical regime (stable, mean-reverting book). - eta -> 1.0: Critical regime (heavy-tailed cascades, order book thinning). - eta >= 1.0: Super-critical regime (explosive liquidity cascades, flash sweep vulnerability). ### D. Kyle's Lambda (Permanent Price Impact) Permanent price revision is modeled as a linear function of net order flow volume Q: delta_P_t = lambda * Q_t + epsilon_t where lambda (pts per thousand Units) is estimated via recursive Ordinary Least Squares (OLS) over sliding windows of execution fills: lambda_hat = [N * sum(Q_i * delta_P_i) - sum(Q_i) * sum(delta_P_i)] / [N * sum(Q_i^2) - (sum(Q_i))^2] ### E. Order Book Imbalance (OBI) & Amihud Ratio - Order Book Imbalance (OBI) across top K levels: OBI_K = [sum_{k=1}^K V_bid,k - sum_{k=1}^K V_ask,k] / [sum_{k=1}^K V_bid,k + sum_{k=1}^K V_ask,k] in [-1.0, +1.0] - Amihud Illiquidity Ratio: I_Amihud = (1 / M) * sum_{t=1}^M [|delta_P_t| / Volume_t] --- ## 3. Production PostgreSQL / AlloyDB Data Schema ```sql -- DDL Schema: APEX-210 Market Microstructure Engine -- Target: PostgreSQL 15+ / Google Cloud AlloyDB -- Strict normalized schema with audit triggers and zero circular foreign keys CREATE SCHEMA IF NOT EXISTS lob_core; CREATE TABLE lob_core.asset_pairs ( asset_pair_id VARCHAR(64) PRIMARY KEY, base_unit VARCHAR(32) NOT NULL, quote_unit VARCHAR(32) NOT NULL, tick_size_pts NUMERIC(10, 4) NOT NULL DEFAULT 0.0500, lot_size_units NUMERIC(14, 2) NOT NULL DEFAULT 1.00, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW() ); CREATE TABLE lob_core.orders ( order_id VARCHAR(64) PRIMARY KEY, asset_pair_id VARCHAR(64) NOT NULL REFERENCES lob_core.asset_pairs(asset_pair_id), side VARCHAR(8) NOT NULL CHECK (side IN ('BUY', 'SELL')), order_type VARCHAR(16) NOT NULL CHECK (order_type IN ('LIMIT', 'MARKET')), price_pts NUMERIC(14, 4) NOT NULL, quantity_units NUMERIC(16, 4) NOT NULL CHECK (quantity_units > 0), filled_units NUMERIC(16, 4) NOT NULL DEFAULT 0 CHECK (filled_units >= 0), status VARCHAR(16) NOT NULL DEFAULT 'RESTING' CHECK (status IN ('RESTING', 'PARTIAL', 'FILLED', 'CANCELLED')), is_user_child_order BOOLEAN NOT NULL DEFAULT FALSE, submitted_at TIMESTAMPTZ NOT NULL DEFAULT NOW(), updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW() ); CREATE INDEX idx_orders_resting ON lob_core.orders (asset_pair_id, side, price_pts, submitted_at) WHERE status IN ('RESTING', 'PARTIAL'); CREATE TABLE lob_core.executions ( execution_id VARCHAR(64) PRIMARY KEY, asset_pair_id VARCHAR(64) NOT NULL REFERENCES lob_core.asset_pairs(asset_pair_id), maker_order_id VARCHAR(64) NOT NULL REFERENCES lob_core.orders(order_id), taker_order_id VARCHAR(64) NOT NULL REFERENCES lob_core.orders(order_id), side VARCHAR(8) NOT NULL CHECK (side IN ('BUY', 'SELL')), execution_price_pts NUMERIC(14, 4) NOT NULL, quantity_units NUMERIC(16, 4) NOT NULL CHECK (quantity_units > 0), price_impact_pts NUMERIC(10, 4) NOT NULL DEFAULT 0.0000, executed_at TIMESTAMPTZ NOT NULL DEFAULT NOW() ); CREATE INDEX idx_executions_timestamp ON lob_core.executions (asset_pair_id, executed_at DESC); CREATE TABLE lob_core.audit_ledger ( block_index BIGINT PRIMARY KEY, block_hash CHAR(64) NOT NULL UNIQUE, prev_hash CHAR(64) NOT NULL, event_type VARCHAR(64) NOT NULL, payload JSONB NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW() ); CREATE INDEX idx_audit_prev_hash ON lob_core.audit_ledger (prev_hash); ``` --- ## 4.
