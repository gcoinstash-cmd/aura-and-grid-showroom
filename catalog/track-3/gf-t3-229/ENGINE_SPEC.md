Analytical 1F1B Pipeline Bubble Derivations ### 2.1 Synchronous GPipe vs. 1F1B Steady-State Schedule Let `p` denote the number of pipeline stages (`p = 4`) and `m` denote the number of micro-batches per step (`m = 16`). Let `t_f` and `t_b` denote the forward and backward execution times of a single micro-batch on a single stage. In a naive synchronous all-forward-then-all-backward pipeline schedule: - **Peak Activation Stash Memory**: `O(m)` activations on Stage 0 (`16` micro-batch activations held concurrently in VRAM until backward passes begin). - **Synchronous Pipeline Bubble Fraction**: `Bubble_Sync = (p - 1) / m` In the **GF-T3-229 1F1B Schedule**: 1. **Warmup Phase**: Stage `s` (for `s in {0, 1, 2, 3}`) executes `w_s = p - s - 1` forward micro-batches: - Stage 0 executes `3` warmup forwards (`F0, F1, F2`), then `F3` enters steady state. - Stage 1 executes `2` warmup forwards (`F0, F1`). - Stage 2 executes `1` warmup forward (`F0`). - Stage 3 executes `0` warmup forwards (immediately pairs `F0` with `B0`). 2. **Steady-State 1F1B Phase**: Each stage alternates `1 Forward` pass followed immediately by `1 Backward` pass. Every completed backward pass immediately frees its stashed activation slot for the incoming forward micro-batch. 3. **Cooldown Phase**: Each stage drains its remaining `w_s` stashed activations via consecutive backward passes. ### 2.2 Strict Activation Memory Bound (`p = 4`) At any discrete step `t`, the number of in-flight stashed activations `A(s, t)` on stage `s` satisfies: `A(s, t) <= p - s <= p` - Stage 0 (`S0`): maximum `4` stashed activations (`2,048 MB`). - Stage 1 (`S1`): maximum `3` stashed activations (`1,536 MB`). - Stage 2 (`S2`): maximum `2` stashed activations (`1,024 MB`). - Stage 3 (`S3`): maximum `1` stashed activation (`512 MB`). This guarantees a **75.0% peak activation memory reduction** on Stage 0 compared to buffering all `m = 16` micro-batches. ### 2.3 Zero-Bubble Interleaved & Non-Blocking P2P Compression Standard un-overlapped 1F1B bubble ratio is: `Bubble_Raw = (p - 1) / (m + p - 1) = 3 / 19 = 15.79%` By splitting backward weight-gradient (`B_W`) and input-gradient (`B_I`) computation and overlapping inter-stage P2P tensor transfers (`0.22 ms` NVLink handoff) with on-device CUDA stream execution (`c_alpha = 0.532`): `Bubble_Effective = Bubble_Raw * c_alpha = 15.79% * 0.532 = 8.4%` --- ## 3.
