# ENGINE_SPEC.md: GF-T3-215 APEX-215 Vector Index & Quantization Engine ## 1. Architectural Topology & System Boundaries The APEX-215 engine is an asynchronous, high-dimensional vector search mesh designed for high-throughput, low-latency approximate nearest neighbor (ANN) retrieval with embedded Product Quantization (PQ) and Asymmetric Distance Computation (ADC). ``` +---------------------------------------+ | Ingestion & Query Gateway | | OpenAPI 3.1 REST / gRPC Streaming | +-------------------+-------------------+ | +-------------------------+-------------------------+ | | +-----------v-----------+ +-----------v-----------+ | HNSW Multi-Layer | | Product Quantizer | | Skip-Graph Mesh | | Sub-space Codebooks | | - Express Layer 2..L | | - M=16 Sub-spaces | | - Base Layer 0 | | - K=256 Centroids | | - Heuristic Pruning | | - ADC Fast Lookup | +-----------+-----------+ +-----------+-----------+ | | +-------------------------+-------------------------+ | +-------------------v-------------------+ | Normalized Relational Store | | PostgreSQL / AlloyDB Vector | | Partitioned Index & Audit Logs | +---------------------------------------+ ``` ### 1.1 Ingestion Flow 1. **Normalization & Sub-Vector Partitioning**: Incoming D-dimensional vector `x in R^D` is optionally unit-normalized (`||x||_2 = 1.0`). 2. **PQ Encoding**: Vector is split into `M` sub-vectors of dimension `d_sub = D / M`. Each sub-vector is mapped to its nearest Voronoi centroid `c in {0..255}`, yielding an `M`-byte quantized signature. 3. **Multi-layer Insertion**: The node is assigned an exponential skip-list layer `l ~ Floor(-ln(Uniform(0,1)) * mL)`. Graph links are formed across all layers `0 <= i <= l` with heuristic degree constraint `M_max` and `M_max_0`. --- ## 2. Proprietary Mathematical & Algorithmic Engine ### 2.1 HNSW Graph Navigation Mechanics Hierarchical Navigable Small World graphs organize elements into a hierarchy of layers: - `Layer 0`: Contains all indexed nodes with maximum degree `M_max_0 = 32`. - `Layer l > 0`: Expressways with exponentially decaying density governed by scale parameter `mL = 1.0 / ln(M_max)`. #### Traversal Algorithm: Given query vector `q`, entry point `ep`, and target search width `ef_search`: 1. For layer `l = L_max` down to `1`: - Greedily descend through layer `l`: Find neighbor `n in Neighbors(curr, l)` that minimizes `d(q, v_n)`. If `d(q, v_n) < d(q, v_curr)`, update `curr = n` and repeat until local minimum. 2. At `Layer 0`: - Initialize candidate priority queue `C = {curr}` and result set `W = {curr}`. - While `C` is non-empty: Pop closest candidate `c from C`. If `d(q, v_c) > max_{w in W} d(q, v_w)` and `|W| >= ef_search`, terminate loop. For each `n in Neighbors(c, 0)`: If `n not in Visited`: Insert `n into Visited`. If `d(q, v_n) < max_{w in W} d(q, v_w)` or `|W| < ef_search`: Insert `n into C` and `W`. If `|W| > ef_search`, evict furthest element from `W`. ### 2.2 Product Quantization (PQ) & Asymmetric Distance Computation (ADC) Let vector space be `R^D` decomposed into `M` orthogonal subspaces: `R^D = R^(d_sub) x R^(d_sub) x ... x R^(d_sub)`, where `d_sub = D / M`. Each subspace `m in {0..M-1}` possesses a trained codebook of `K = 256` Voronoi centroids: `C_m = {c_(m, 0), c_(m, 1), ..., c_(m, 255)}`. A database vector `x` is represented by its quantized byte sequence: `q_code(x) = [k_0, k_1, ..., k_(M-1)] in {0..255}^M`. #### Asymmetric Distance Computation Formulation: For an uncompressed query `q in R^D`, the distance to any quantized vector `x` is computed without vector decompression: 1. Precompute distance lookup table `LUT in R^(M x 256)`: `LUT[m, k] = ||q_m - c_(m, k)||^2` for all `m in {0..M-1}` and `k in {0..255}`. 2. Approximate distance calculation: `d_ADC(q, x) = sqrt( sum_{m=0}^{M-1} LUT[m, q_code(x)[m]] )`. Computational complexity per candidate: `O(M)` table lookups and additions. Zero floating-point multiplications. --- ## 3.
