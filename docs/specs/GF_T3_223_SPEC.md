# GF-T3-223 — Enterprise Reference Core Specification **Project Identifier:** `GF-T3-223` **Catalog Classification:** `TRACK 3 — PRODUCTION REFERENCE CORE` **Domain:** Speculative Decoding Harness · Draft Verification · Rejection Sampling · Dynamic K Horizon --- ## 1. Architectural Topology & Container Boundaries `GF-T3-223` is a self-contained, clean-room speculative decoding coordinator and lossless batch verification engine engineered for low-latency autoregressive token acceleration. ### 1.1 Service Boundaries & Ingestion Pipeline 1. **Draft Speculation Tier (`DraftGenerator`):** Lightweight autoregressive worker generating `K` speculative candidate tokens (`K in [2, 8]`) sequentially along with full categorical probability distributions `P_draft(x_i | x_<i)`. 2. **Parallel Target Verification Tier (`BatchTargetVerifier`):** Evaluates all `K` draft prefixes in a single parallelized matrix-matrix forward pass, yielding `K + 1` exact target conditional distributions `P_target(x_i | x_<i)` in `O(1)` step latency. 3. **Lossless Rejection Sampling Kernel (`RejectionSamplingGate`):** Applies exact token-level acceptance criteria and positive residual resampling `(P_target - P_draft)+` upon first divergence. 4. **Adaptive Horizon Controller (`DynamicKTuner`):** Computes rolling token acceptance rate `alpha` and dynamically expands or contracts the speculative lookahead window `K` to prevent target pipeline stalls. ### 1.2 Synthetic Speculative Corridors - `SPEC-CORRIDOR-ALPHA (DRAFT-K4 · HIGH-ENTROPY-VERIFIER)` — Default `K = 4`, Draft Step `0.85 ms`, Target Batch `11.4 ms`, Baseline Acceptance `72.0%`. - `SPEC-CORRIDOR-BRAVO (DRAFT-K6 · CODE-COMPLETION-FASTPATH)` — Default `K = 6`, Draft Step `0.78 ms`, Target Batch `12.1 ms`, Baseline Acceptance `86.0%`. - `SPEC-CORRIDOR-GAMMA (ADAPTIVE-HORIZON-BALANCER)` — Default `K = 5`, Draft Step `0.84 ms`, Target Batch `12.1 ms`, Baseline Acceptance `78.4%`. - `SPEC-CORRIDOR-DELTA (REJECTION-SAMPLING-FALLBACK)` — Default `K = 3`, Draft Step `0.92 ms`, Target Batch `11.8 ms`, Baseline Acceptance `54.0%`. --- ## 2. Proprietary Mathematical & Algorithmic Engine ### 2.1 Exact Rejection Sampling Invariant (Zero Quality Loss Proof) Let `P_draft(x)` denote the draft distribution and `P_target(x)` denote the target distribution over finite vocabulary `V`. For a draft candidate token `x ~ P_draft`: 1. **Acceptance Rule:** Draw `u ~ Uniform(0, 1)`. Accept candidate token `x` if: ```text u < min(1, P_target(x) / P_draft(x)) ``` Equivalently, if `P_target(x) >= P_draft(x)`, accept deterministically (`threshold = 1.0`); otherwise accept with probability `P_target(x) / P_draft(x)`. 2. **Residual Resampling Upon Rejection:** If `x` is rejected at position `j`, truncate all subsequent draft candidates `j+1 ... K` and sample replacement token `x_res` from the normalized positive residual distribution: ```text P_res(x) = max(0, P_target(x) - P_draft(x)) / sum_{v in V} max(0, P_target(v) - P_draft(v)) ``` 3. **Proof of Exact Marginal Alignment:** The total probability mass accepted directly across vocabulary `V` is: ```text sum_{v in V} P_draft(v) * min(1, P_target(v) / P_draft(v)) = sum_{v in V} min(P_draft(v), P_target(v)) ``` Therefore, the probability of rejection at step `j` is: ```text R = 1 - sum_{v in V} min(P_draft(v), P_target(v)) = sum_{v in V} max(0, P_target(v) - P_draft(v)) ``` For any specific token `x in V`, the marginal probability of emitting `x` is: ```text P(emit x) = P_draft(x) * min(1, P_target(x) / P_draft(x)) + R * P_res(x) = min(P_draft(x), P_target(x)) + R * (max(0, P_target(x) - P_draft(x)) / R) = min(P_draft(x), P_target(x)) + max(0, P_target(x) - P_draft(x)) = P_target(x) ``` Thus, `P(emit x) == P_target(x)` identically for all `x in V`. ### 2.2 Expected Token Yield & Wall-Clock Speedup Derivation Given stationary token acceptance probability `alpha in [0, 1]` and draft window horizon `K`: ```text E[Committed Tokens per Cycle] = (1 - alpha^(K + 1)) / (1 - alpha) for alpha < 1 E[Committed Tokens per Cycle] = K + 1 for alpha == 1 ``` Let `T_draft` denote single-step draft latency (`ms`) and `T_target` denote single-forward-pass batched target verification latency (`ms`). The wall-clock speedup ratio `S(K, alpha)` is: ```text S(K, alpha) = (E[Committed Tokens per Cycle] * T_target) / (K * T_draft + T_target) ``` At reference calibration (`K = 5`, `alpha = 0.784`, `T_draft = 0.84 ms`, `T_target = 12.1 ms`): - `Draft Latency = 5 * 0.84 ms = 4.20 ms` - `Verification Step = 12.10 ms` - `Cycle Latency = 16.30 ms` - `Expected Committed Tokens = (1 - 0.784^6) / (1 - 0.784) = 3.554 tokens` - `Speculative Speedup = 2.45x` (including memory barrier synchronization overhead) --- ## 3.
